# Análisis de SonarCloud fuera del gate (KNOCK-297)

## Qué cambió
`.github/workflows/sonarcloud.yml`: workflow aparte que, al terminar `ci-pr` por un push a `main`, descarga el artefacto `api-reports` de esa corrida, convierte su `Cobertura.xml` al formato de Sonar, compila y envía el análisis con SonarScanner para .NET. Usa el secreto `SONAR_TOKEN` y las variables `SONAR_ORGANIZATION` y `SONAR_PROJECT_KEY`; si falta alguno, avisa y se omite.

## Por qué
Mostrar calidad y cobertura en SonarCloud sin tocar el gate. El plan gratuito solo analiza la rama principal y los PR; aquí solo se analiza `main` y no se expone el token a código de PR.

## A evitar
No agregar este workflow al gate ni a la protección de ramas. No pasarle el token a corridas de PR. No poner `sonar.branch.name` para `main`. No habrá análisis hasta que el archivo esté en `main` (un `workflow_run` solo corre desde la rama predeterminada); llegará con la promoción (paso 3).
